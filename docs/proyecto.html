Propuesta para revisión · Hackathon Solana

Software que cumple.
Pagos que se liberan automáticamente.

Cliente y proveedor acuerdan requisitos claros. El Frontier Agent verifica cada hito y, cuando cumple, el sistema liquida automáticamente su pago desde un escrow en Solana.

Producto definido; prototipo previsto en local/devnet. No se presenta como sistema implementado, auditado o habilitado para fondos reales.

Problema

El cliente teme pagar sin recibir lo acordado. El proveedor teme entregar sin cobrar.

Solución

Fondos reservados, código verificable y pagos progresivos por cumplimiento, no por horas o commits.

Usuarios

Clientes, freelancers y factories. Acceso con Phantom; se evalúa el código, no el tipo de proveedor.

Cómo funciona

  1. 1 → AcordarDocumento, escenarios legibles e importe por hito. Ambas partes aceptan las reglas.
  2. 2 → FinanciarEl cliente reserva los fondos del trabajo cubierto en escrow.
  3. 3 → VerificarPipeline + Frontier Agent: pruebas y revisión. Si falla, informa qué corregir.
  4. 4 → PagarAprobación válida → pago automático + comisión porcentual pactada.

Sin aprobación manual rutinaria por entrega ni botón obligatorio para cobrar. Un resultado inconcluso queda en espera, sin pago.

Solana no evalúa el software: hace cumplir las condiciones económicas. Código y documentos privados permanecen fuera de cadena.

Correcciones

El agente comenta; el proveedor corrige. Cambiar código aprobado invalida la evidencia para la nueva revisión.

Disputas

Resuelve una persona de la plataforma. Una disputa activa bloquea el pago afectado todavía pendiente.

Demostración

Un hito cobrado; otro fallido, corregido y luego pagado. Evidencia y transacciones sin duplicados.

Qué buscamos validar con la dirección

El encaje de la propuesta y una demo que conecte cumplimiento verificable → aprobación → pago automático por hitos.

Al implementar se concretan activo y porcentaje, permisos humanos, orden disputa/pago y límites del bloqueo técnico. No se garantiza ausencia de bugs.
